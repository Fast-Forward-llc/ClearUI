# ClearUI Tag Helpers

ClearUI Tag Helpers is a set of ASP.NET Core Razor Pages tag helpers that bridge server-side model binding with the [ClearUI Vue Components](../ClearUI/VueComponents/Readme.md) library. They let you author `cui-*` elements using familiar `asp-for`-style attributes, and automatically wire up the `id`, `name`, `v-model`, `label`, `:value`, and other bindings that the Vue components expect.

## Why use it?

Without these tag helpers, using ClearUI Vue components in a Razor Pages form requires manually wiring `v-model`, `id`, `name`, and `label` bindings to match your page model. `ClearUITagHelpers` removes that boilerplate by extending the `cui-*` elements with `asp-for`-based attributes, following the same conventions as built-in ASP.NET Core tag helpers like `asp-for` on `<input>`.

```html
<!-- Without tag helpers -->
<cui-textbox id="Email" name="Email" v-model="Email" label="Email" />

<!-- With tag helpers -->
<cui-textbox asp-for="Email" />
```

## Getting Started

1. Reference the `ClearUITagHelpers` project/package from your Razor Pages (or MVC) project.
2. Register the tag helpers in `_ViewImports.cshtml`:

    ```cshtml
    @addTagHelper *, ClearUITagHelpers
    ```

3. Use `asp-for` (and the other `asp-for:*` attributes below) on any `cui-*` element in your Razor views/pages.

## Tag Helpers

### `BaseVueInputTagHelper`

The common base class applied to all `cui-*` input-style elements. It is not targeted directly at any element itself, but supplies shared behavior to the tag helpers below:

- `asp-for` — binds to a model property (consumed by `InputControlTagHelper`, `GridTagHelper`, and `ErrorSummaryTagHelper`).
- `asp-for:value` — sets `:value` from a model expression.
- `asp-for:v-model` — sets `v-model` (or `v-model.lazy`, if any bound attribute includes a `.lazy` modifier) from a model expression.
- `asp-for:list-items` — sets `:list-items` from a model expression.
- Normalizes plain HTML `readonly` / `required` attributes to Vue's `:readonly="true"` / `:required="true"` bindings.
- Cooperates with `SuppressPrefixTagHelper` to strip a model prefix (e.g. for nested/complex model binding scenarios) from generated names.

### `InputControlTagHelper`

Targets: `cui-textbox`, `cui-textarea`, `cui-checkbox`, `cui-checkbox-grp`, `cui-radio-btn`, `cui-radio-grp`, `cui-switch`, `cui-dropdown`, `cui-tree-list`.

When `asp-for` is supplied and the corresponding attribute isn't already present, automatically sets:
- `v-model` (or `v-model.lazy`) to the model property name
- `id` to the model property name
- `name` to the model property name
- `label` to the property's display name (or property name, if no display name is configured)

```cshtml
<cui-textbox asp-for="Email" />
<cui-dropdown asp-for="Country" asp-for:list-items="Countries" />
```

### `GridTagHelper`

Targets: `cui-grid`.

Adds model-expression-based bindings for grid-specific props:
- `asp-for:grid-items` → `:grid-items`
- `asp-for:caption` → `:caption`
- `asp-for:column-config` → `:column-config`

```cshtml
<cui-grid asp-for:grid-items="Rows" asp-for:column-config="Columns" asp-for:caption="GridCaption" />
```

### `ErrorSummaryTagHelper`

Targets: `cui-error-summary`.

When `asp-for` is supplied, automatically sets:
- `:errors` to the model property name (if not already bound)
- `heading` to the property's display name (or property name, if not already bound)

```cshtml
<cui-error-summary asp-for="Email" />
```

### `HttpRequestTagHelper`

Targets: `cui-http-request` (when used with `asp-action`/`asp-controller`, or as a self-closing element).

Resolves an ASP.NET Core route (via `asp-controller`, `asp-action`, and optional `asp-route-id`) into a `url` attribute for the component, the same way `asp-controller`/`asp-action` work on `<a>` and `<form>` elements. If a `url` attribute is already supplied directly, route resolution is skipped.

```cshtml
<cui-http-request asp-controller="Home" asp-action="VirtualScrollData" />
```

### `SuppressPrefixTagHelper`

Targets: any element with a `suppress-asp-model-prefix` attribute.

Used on a containing element (e.g. a form or fieldset wrapping a nested/complex model) to strip a leading prefix (the bound model expression's name) from names generated by `asp-for` on descendant `cui-*` elements. This is useful when a page model wraps a sub-object but you don't want the sub-object's property prefix embedded in generated `id`/`name`/`v-model` bindings.

```cshtml
<div suppress-asp-model-prefix="Address">
    <cui-textbox asp-for="Address.Street" /> <!-- generates id="Street", not "Address.Street" -->
</div>
```
